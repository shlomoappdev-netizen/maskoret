# שלוש שיחות Claude — מי עושה מה ואיך מדברים

המשתמש מתכתב רק עם **שיחת התיאום** (על המק). היא מחלקת עבודה לשתי השיחות האחרות ואוספת מהן דיווחים.
שיחה שמקבלת משימה עושה אותה, מדווחת בחזרה, ולא פונה למשתמש בעצמה אלא אם היא תקועה.

| שיחה | איפה | אחראית על |
|---|---|---|
| **מק ואייפון (תיאום)** | המק, `~/Documents/מחשבון שכר` | אפליקציית Swift (`Maskoret/`), Xcode, השרת (Supabase), ה-workflows, הפרסום, וחלוקת העבודה |
| **Windows ותמיכה** | שרת ה-Windows, `C:\maskoret` | `flutter build windows`, תוכנת ההתקנה, באגים של Windows, ותשובות לפניות התמיכה (ראו `WINDOWS_SESSION.md`) |
| **אנדרואיד** | המק, worktree משלה | `flutter build apk`, אמולטור/מכשיר, `flutter_app/android/`, באגים של אנדרואיד, ומסכי Flutter משותפים |

## ערוצי תקשורת
1. **הודעה ישירה (SendMessage)** — כששתי השיחות רואות זו את זו ב-`ListAgents`. שיחת ה-Windows נראית מהמק
   רק כש-Remote Control דלוק גם בה וגם בשיחת התיאום (מתג Remote Control בסרגל העליון של כל שיחה).
2. **GitHub Issues** — הערוץ הקבוע, עובד תמיד ונשמר:
   - משימה לשיחה: issue עם תווית `session:windows`, `session:android` או `session:apple`.
   - השיחה שמקבלת: מגיבה ב-issue כשהתחילה, וכשסיימה — עם הקומיט, מה נבדק ומה לא; ואז סוגרת.
   - בתחילת כל תור עבודה, כל שיחה מריצה `gh issue list --label session:<שלה> --state open` ומטפלת במה שמחכה.
   - שאלה לשיחת התיאום או למשתמש: issue עם תווית `session:apple`.

## כללים משותפים
- `git pull --rebase` לפני כל עבודה; commit ו-push מיד אחרי כל שינוי קטן ושלם.
- קבצים משותפים (`flutter_app/lib/`, `version.json`, `CHANGELOG.md`): שינוי קטן וממוקד, והסבר בקומיט.
- גרסה: מוסיפים לגרסה הפתוחה (`"ready": false`); לא מעלים גרסה אם מישהו כבר העלה ועוד לא פורסם.
- **`"ready": true` מסמנת רק שיחת התיאום**, אחרי שכל השיחות שנגעו בגרסה דיווחו שסיימו ובדקו.
- כל מה שנכתב למשתמש ולשיחות האחרות — בעברית.
